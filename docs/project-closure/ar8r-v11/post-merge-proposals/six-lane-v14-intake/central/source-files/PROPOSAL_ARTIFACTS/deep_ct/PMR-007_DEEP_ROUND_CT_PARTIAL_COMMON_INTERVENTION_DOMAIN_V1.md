## Candidate setting

Let `M` be a finite architecture class, `E:M→Obs` the current complete profile,
`Q:M→Target` the architecture target, and `a` a proposed intervention with
implementation domain `D_a⊆M`. For `m∈D_a`, the intervention returns an outcome
`Y_a(m)`.

A candidate totalization adjoins a special symbol `⊥` and reports

```text
T_a(m) = (E(m), Y_a(m))      when m in D_a;
T_a(m) = (E(m), bottom)      otherwise.
```

## V1 candidate claim

If `D_a` is a proper subset of `M`, then `a` cannot identify `Q` over `M`, even
when nonimplementation is recorded as `⊥`.

The intended application is to block a proposed intentional-uptake,
first-person-ownership, or source-intensional operation that is available only
under the preferred personal architecture.

## Intended nonclaims

The candidate does not claim that a genuinely common target-blind capability
measurement cannot refine `E`, nor that no future experimental interface can
separate the current U/I collision.
