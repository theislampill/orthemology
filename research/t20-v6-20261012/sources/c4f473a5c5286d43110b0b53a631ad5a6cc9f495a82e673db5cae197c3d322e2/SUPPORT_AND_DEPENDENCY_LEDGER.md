# Support and dependency ledger

## The full authority basis is larger than the disputed checker

The actual local task fixes a particular source and asks for exact recovery and honest disclosure. The weak C0 checker is subordinate to that task standard. Source identity, finite-string reasoning, local write authority and source-retention obligations remain available when C0 is replaced. The basis is declared before assessing the repair; it is not narrowed after success to create an appearance of full-basis radicality.

## Mechanism support inventory

The reference implementation is one Python process. Its source store, active grant store, actor binding, clock reading, revision comparison, exact-byte check, branch logic, append-only-history update and write operation all depend on that process and its environment. Their different field names are not independent physical fault roots. No B-fault guarantee is claimed for the Python program.

The Lean verifier supplies a proof about the typed transition, not an independent runtime interlock. The compiler, interpreter and operating environment remain part of the computation chain. Cross-language replay is a bounded check of agreement over declared fixtures; it is not a proof that a malicious environment cannot make both runs lie, and it is not a universal compiler-correctness theorem.

Any deployment using a live commitment would additionally need an authenticated grant policy, source-binding route, trusted or redundantly protected time/currentness observations, a non-bypassable gate and an accounted executor. A signed lease without those supports records a past claim; it does not make the future intervention safe.

## Dynamic-lane interface

The dynamic repair lane owns the q-root/r-root overlap theorem. Its proposed discharging mechanism uses lifetime-union taint ≤B, live physical conjunctions, and institutional authorization that remains valid until revocation completion. Its exact support bound is conditional on that family. This lane does not independently attest that the institution is legitimate for a recipient whose consent is immediately revocable.

The reusable semantic segment supplied here is:

1. fixed target identity T
2. actual byte sequence S through the declared source route
3. the retained fidelity obligation M
4. a proof that C1 tracks M and C0 does not
5. the exact command payload S and the unaffected custody conditions

The independently regenerated contextual segment is:

1. actual actor and destination
2. current draft revision and authorization epoch
3. legitimate operation scope and current permission
4. observation/intervention ordering and lease bounds
5. mechanism's active commitment, revocation status and actual support set

The pure reference model computes these semantic and contextual conditions from trusted typed state. It does not implement a signing protocol, root quorum, real-time lease service, or cryptographic authentication. The external mechanism fields belong to the typed interface contract; they must not be mistaken for implemented evidence.

## Foundational deletion

The proof and code have no parameter for necessary-source N2, P1 productive completion, P2 particular-bearer identification, original cognitive possession, essential truthful attestation T0, Wisdom or metaphysical unity. The same local source/criterion/permission facts can be held fixed under differing ultimate explanations. Removing any of those source/attribute premises leaves every local result unchanged.

This is a dependency audit, not a countermodel establishing the metaphysical possibility of every ultimate explanation. It withdraws the inference that this operational result itself supplies a foundational bridge.
