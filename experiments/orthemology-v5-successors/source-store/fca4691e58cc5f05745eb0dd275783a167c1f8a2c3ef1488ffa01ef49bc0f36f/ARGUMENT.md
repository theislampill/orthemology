# From compiled criterion repair to charged execution

## Result and precise ceiling

The two exact predecessors are conditionally compatible. The delivered composition actually calls the imported Lean installation/data-repair functions at proposal and at live landing checks. Their returned booleans and successor fields control whether the modeled plant can change and what it changes to. It is not a Python checker used after discarding Lean output.

For the pinned source, the compiled sequence installs `.exact` in place of `.normalizedLF`, changes the installed interpreter's acceptance of the defective extra-LF draft, preserves that draft during installation, and subsequently repairs it under a distinct `replace-derived` grant. Both changes preserve the exact original source and custody fields. At `n=4,B=1,q=r=3,cancel_threshold=2`, the four-path portfolio completes each stage in a stable authorized window despite one lifetime-tainted root withholding execution. This is a bounded mathematical/reference-execution result, with stronger typed-plant observation premises than either predecessor alone.

It is not a physically distributed implementation, compiler-correctness result, proof of real permission, arbitrary-code updater, unlimited mobile-fault guarantee, N2/T0 argument, Candidate E adoption, R5 defeat, or canonical closure. The author’s native replay is not an independent review.

## 2. Mismatches and the actual extension

### Identity and version coordinates

The dynamic predecessor writes a binary table and distinguishes target version from control epoch. Here the source target is the repository/commit/path triple. Installed rule version, derived draft revision, and permission epoch are separately typed record fields. No target version is cast into a draft or rule version.

`Plant` holds source, destination, retained standard, draft/revision/history, installed rule/version/history, and unrelated custody. `Policy` holds the locally received target, actor, destination, operation scope, epoch, grant and allowed bit. The source rule terms retain the exact imported two-constructor semantics; no user-supplied function receives trust by carrying a C1 label.

### Source transitions and full successor binding

`localStep` calls `CriterionInstallation.install` on a view of the actual Plant plus local Policy and observed time. Only an applied source outcome produces a successor; that successor projects exactly the returned rule/version/history into the Plant. Its complete effect and full frame are proved.

The repair branch requires the actual installed `.exact` constructor, calls its interpreter on the candidate bytes, then calls `TypedCriterionGuard.execute`. It projects exactly the returned draft/revision/history while retaining rule/version/history. The C1 protocol string is therefore not the sole interpretation of installed rule identity.

The interpreter check on a valid exact payload is extensionally redundant with the imported exact-payload guard once `.exact` is established. It is still an actual consumed runtime Boolean. No claim is made that deleting only that redundant conjunct would yield a new extensional counterexample. Deleting the installed-rule gate as a whole is detected by runtime tests. The separate before/after acceptance observation directly exercises the installed interpreter on the bad draft, where C0 and C1 differ.

An `Envelope` binds the typed command, full proposed successor, unique nonce and actual path. Every intact root recomputes `localStep` on the same actual atomic Plant, its own local policy and its correct time observation, and requires exact equality with that successor. This prevents stale whole-record overwrite: installation cannot overwrite an intervening draft change, and data repair cannot overwrite an intervening rule-version/history change even though the original data command has no rule-version field.

### Live mediation and observation

The only mutation is the atomic event `Plant := envelope.successor` when every selected gate permits that exact envelope. The execution function never consults `World.effectivePolicy`; it is used for owner-transition state and theorem/classification purposes. The actor proposes solely from its received policy, observed plant and explicitly stored `Actor.observedTime`. `propose` has no World or separate current-time input; `runBatch` cannot substitute `World.now`. Authenticity of the stored time observation is a correct-actor premise, not a fact established by the field. It may be old, and policy-certificate delivery does not silently refresh it. A stale actor can remain ignorant of a completed revocation and still be safely blocked.

This adds an explicit plant interface: each intact selected root independently observes the same current complete Plant within the indivisible read/check/land operation and retains a veto on the exact successor. The shared recipient Plant is the mathematical transition boundary, not a new supposedly trusted process. Any corruptible shared reader, writer, selector or clock service must be charged in the real support map; naming four roots does not make such shared dependencies disappear.

`World.now` represents the actual time fact observed correctly by each intact root at that step. Its use in this single-process reference is not proof of a clock architecture. Per-root observation correctness, including time, is a charged duty. The grant interval remains `notBefore ≤ now < expires` and `observedAt ≤ now < leaseEnd ≤ expires`. Logical service phases do not themselves establish a physical-time duration.

## 3. One consistent permission contract

Each accepted source transition requires a grant for the actual actor, destination, target, epoch and operation, within the checked interval. An installation grant cannot authorize draft repair. The two-stage trace receives a distinct owner-provided repair Policy in a later certified control epoch; it does not derive that grant from criterion adequacy or mint permission itself.

The modeled authority institution keeps the old reserved action right valid until effective certificate completion, or otherwise physically closes all affected paths before actual external consent ends. A request is not automatically an effective revocation. Immediate external withdrawal invisible to every root is incompatible with that institution; the retained negative test changes effective external permission without delivering a revocation and shows that an old action can still land. No definitional relabeling turns that trace into legitimate action.

Correct roots retain authentic serial descriptors, never a future uncompleted policy, and share the same authoritative descriptor at a given epoch. For a completed old-epoch revocation, an r-set contains enough durable revocation memories to intersect every q-path in an intact gate. Under those assumptions, `landed_refines_effective_policy` proves that any actual accepted landing equals an accepted imported transition under the currently effective Policy. The theorem obtains a local witness, proves its command epoch cannot be future, excludes older epochs using the imported dynamic overlap argument, and substitutes the unique current policy. Actual institutional legitimacy remains a premise beyond that theorem.

## 4. Charged root/cancellation mechanism

The same root unit owns source checking, complete binding, local grant/epoch and time observation, commitment/cancellation memory, authentication, transport/control support and live veto. A root is lifetime-tainted if any of these relevant duties fail, even if its other responses are truthful. Every named safety/progress conclusion assumes the same union of ever-tainted roots has size at most B during the whole horizon.

Preparation may be mimicked by bad roots. At landing, bad roots may open or withhold their own gate; they cannot suppress an intact root’s veto or replace bytes after its check. Every write remains mediated. Direct path addressability and independent per-root control-port service remain the dynamic v2 assumptions, not facts proved by sequential function calls.

Cancellation checks the original recipient’s separately retained cleanup right and counts distinct selected roots. A correct root stores the full-envelope tombstone before replying, even after action permission is revoked. `cancel_threshold=B+1` acknowledgers contain an intact root, so cancellation permanently blocks a late copy. The final memory cannot be undone by a delayed prepare. New nonces remain available. A lawful landing before closure persists; cleanup does not roll it back.

The Lean cancellation and revocation theorems instantiate the imported root-count lemmas with the actual `rootPermits` predicate. They explicitly assume the relevant good-root tombstones/revocations exist; the protocol’s update functions are executed and exhaustively tested at the stated finite interface. There is no general kernel proof that arbitrary histories of the whole function-level protocol preserve every applicability invariant. The ordinary induction on legitimate transitions supplies that model-level link; actual physical implementation remains unproved.

## 5. Replacing the predecessor’s idempotence step honestly

The source installation increments rule version/history, and data repair increments draft revision/history. Repeated application is therefore not literally idempotent. Importing the predecessor’s table-idempotence theorem unchanged would be false.

For a fixed action a and a successful source step `p → p′`:

- Installation success implies `a.expectedVersion = p.ruleVersion` and `p′.ruleVersion = p.ruleVersion+1`; all draft/source/custody fields are unchanged.
- Repair success implies `a.expectedRevision = p.draftRevision` and `p′.draftRevision = p.draftRevision+1`; all rule/source/custody fields are unchanged.
- A second success of that same a from p′, under any later Policy and time, would require the old expected natural number to equal its own successor. Lean proves the contradiction.
- Every further fixed-envelope attempt has an intact root and therefore cannot pass. Rejection is full World identity at the landing step, not merely equality of the displayed rule label.

`successor_cannot_reland_fixed_action` lifts this argument to the actual gates; it does not depend on cancellation. `attempted_goals_persist` separately proves that once the installed rule is exact and the draft equals source, any later mediated accepted install/repair preserves those goals, while a rejected attempt leaves everything unchanged. This covers fresh valid actions as well as old replays. It does not claim that every valid fresh install leaves the audit history numerically unchanged.

## 6. Ordinary bounded progress proof

Fix `n=4,B=1,q=r=3,cancel_threshold=2`. Assume actor and all intact roots receive the same stable appropriate Policy, the actor has a correct initial Plant observation and an authentic stored time observation that admits the chosen proposal, the source guard is valid for the chosen action, the lease remains valid throughout the batch, no competing plant write occurs during it, intact service meets each phase bound, and the horizon has enough remaining slots.

Enumerate `[012,013,023,123]`. Every attempt uses a fresh nonce but the same action and proposed successor. Before the first landing, the Plant is still the initially observed p. At least three roots are intact, so one path is wholly intact. When reached, all of its preparations and live checks accept the genuine compiled source step and it lands p′ before cancellation begins. Earlier tainted paths may either withhold or perform the same lawful landing. If one already landed, the objective is already achieved and all subsequent old-action copies reject by the preceding theorem. Cancel every attempt regardless of the reported effect; do not stop on an untrusted success label.

There are at least two intact roots in every selected three-root path, so independent bounded cleanup can collect two acknowledgements even if the bad root withholds. An attempted delayed landing after closure is impossible. Thus each batch finishes in at most four macro-attempts, or at most twelve unit logical phases. This is an upper bound at the declared service interface. It is not a wall-clock promise or a fresh lower-bound theorem for arbitrary criterion repair architectures.

For the two-stage trace, first provide a sufficiently long install-authorized stable window, then legitimately certify and deliver the distinct repair Policy, then provide its stable window. The first batch guarantees the exact predicted installed Plant, including histories, without trusting success receipts; the second actor can use that guaranteed observation. The second batch repairs the draft. At most eight new macro-attempts/twenty-four unit logical phases cover the two batches; grant issuance/certificate dissemination and any residual earlier attempt latency are additional. Final quiescence alone cannot recover a permanently withdrawn first-stage grant, and no claim to do so is made.

## 7. Verification evidence and limits

The official Lean 4.19.0 compiler kernel-checks the imported and new theorems, emits C for all modules, and `leanc` links a native executable. The executable directly runs 88 named assertions and writes complete before/installed/repaired Plant JSON and exact source/draft byte files. Five two-batch scenarios exercise 40 macro-attempts. Full-record assertions verify both histories and versions, source, destination, standard and unrelated fields. Negative perturbations cover stale records, copied grants, wrong recipient, changed source, expired landing, successor tampering, installed C0 with a C1 string, stale actor policy, and cancellation races.

The proof log prints actual dependencies. New results use only the standard Lean logical axioms `propext`, `Classical.choice` and `Quot.sound` as listed. No custom axiom, `sorry`, `native_decide`, unsafe definition or external truth oracle is added. Native execution still depends on compiler/runtime/OS correctness; kernel proof checking does not certify those mechanisms.

Proofs are universal only at their stated typed interfaces. The complete protocol replay is bounded. String identity is not authentication, a simulated clock is not a warranted clock service, and an owner Policy fixture is not an actual grant. No common-bearer or sourcehood conclusion follows from composing these operational tracks. The original R5 control is not retroactively endowed with these new interfaces; the narrower result is that no R5 defeat or N2/T0 dependence has been established.
