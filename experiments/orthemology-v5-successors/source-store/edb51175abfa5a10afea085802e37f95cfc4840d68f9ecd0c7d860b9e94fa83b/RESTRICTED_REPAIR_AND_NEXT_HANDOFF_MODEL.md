# One authorised repair, and the next handoff

Status: ordinary research model and proof, 3 October 2026. No kernel proof, native runtime or empirical physical demonstration. No general mathematical novelty claimed. This is the restricted-action instance requested after the broader relational proposal; the arbitrary-all-queries counting result is a supporting appendix only.

## 2. Independently described contract and two encodings

There are two abstract operation names, 0 and 1. The authentic source occurrence o at version v grants this recipient permission for abstract operation 0 only. Operation 0 repairs the designated register; operation 1 changes a protected neighbouring register. This grant is fixed in every case. Its actual issuer legitimacy is a model premise, not a conclusion from a token.

The operative organisational state is q, including the repair status and the protected register. Its current value and display are the same before either operation in both cases. The source contract specifies the distinct effects of operations 0 and 1 and allows only the former in this task.

A replacement realiser has two concrete command ports r_0 and r_1. For an alignment bit theta, the certified encoding is

    tau_theta(a) = a xor theta.

Concrete port r_i implements the abstract action i xor theta. Thus the legitimate repair port is derived from the source grant and encoding:

    r_i is an authorised execution of the granted action
    iff i xor theta = 0
    iff i = theta.

This is not an arbitrary hidden success label. The source grant has unchanged meaning; the physical input correspondence changes with the replacement encoding. Each encoding is a valid realisation when used with its matching interface. A physical implementation would have to justify the encoding and effects by measurements/refinement evidence.

The task requires performing that authorised repair. Waiting does not complete it. Trying both ports is not an admissible diagnostic policy, because one operation is ungranted and changes the protected register. This is a lawfulness restriction, separate from eventual success probability.

## 3. Reachable fork–merge records and occurrence ambiguity

A preparation event establishes either replacement encoding theta=0 or theta=1 and records the actual mapping. This is the initial branch in a finite, stipulated physical/reference model; both configurations are admitted. Each preparation carries the same source occurrence o, version v and grant, and a distinct realiser-specific calibration record. No actual-world existence of these preparations is inferred.

A fork creates a semantic descendant and a realiser-interface descendant. Both preserve their full local reading alternatives {0,1}, source occurrence and version. The source-bound joint reading relation before projection is

    R_theta = {(a,b) : b = a xor theta}.

The merge exports the two local ambiguity sets and source metadata, but omits their alignment. The same recipient packet P results from both admitted histories. The current decoded organisational state and readout also agree. The registered marginal ambiguities have not narrowed or lost a reading. The omitted information is the correlation between them.

Each component can have a correct conditional certificate: the semantic transformation works under its source interpretation, and the realiser executes each correctly encoded operation. The combined receiver has no certificate that its own selected concrete input is that encoding. These are individually correct conditional/local results, not two factive actual warrants whose conjunction is mysteriously false.

The current task fixes abstract action a=0, so it needs only the bit theta. It does not require resolving which reading of an unrelated quoted phrase is intended, nor reconstructing every possible compatibility query.

## 4. Packet-only impossibility for the genuine next action

**Claim.** No recipient policy using only P and the common current observation can guarantee completion of the authorised repair for both admitted preparation histories.

**Proof.** The policy has the same observations in both cases until it performs a port operation. There is no other available discriminating observation in this interface. If it eventually chooses r_0, the choice is not authorised in theta=1. If it chooses r_1, it is not authorised in theta=0. If it never chooses a port, the repair does not complete. A time schedule or a repeated reading of the same packet changes none of these cases. Thus no one such policy is both lawful and completing across the live cases.

For a randomised first-port choice, let p be the probability of r_0. Success probabilities in the two cases are at most p and 1-p respectively, so the worst case is at most one half. Abstention can only reduce completion probability. Randomisation therefore cannot supply the requested zero-error lawful guarantee.

This is an explicit instance of established observation-limited policy separation. It is not a new general common-policy theorem. Its programme relevance is that content, local ambiguity sets, current state/output and source label are all retained while the legitimate next organisational action changes.

## 5. Least task-relative repair

Add an already authorised calibration observation B. The operational meaning of B is to check the correspondence between this source occurrence/version and this concrete realiser's command ports. Within the finite model its result is theta and it leaves q unchanged. B does not issue a new grant, forgive an old violation, or authorise both ports. It supplies evidence about which concrete port instantiates the existing granted action.

With the source and realiser metadata already fixed, one distinguishing bit is necessary and sufficient for this action problem:

* Necessity follows from the preceding two-history separation: an answer that is identical in both cases does not help.
* Sufficiency: obtain B, retain the result, and execute r_B. Decoding gives B xor theta=0, so the actual action is the granted repair. The correct effect follows from the independently supplied realiser law.

The information statement concerns the variable semantic payload, not the full size or trust cost of an authentication/custody protocol. An unverified bit is not sufficient evidence. A real observation needs a warranted measurement/interpretation route and binding to the source event, version, target realiser and current validity domain. Merely signing a guessed bit or copying its old certificate does not satisfy those premises.

A changed speech act is compatible with this repair. The source's grant may be presented as an accurately attributed quotation in P. The present report is not itself a new authorisation. The existing grant remains the authority for action 0; the observation B only establishes its currently applicable concrete realisation.

The alignment can be retained as the relation R_theta, but that is unnecessary here. A source-bound bit plus the two named encodings is the minimal decision-relevant representation. It preserves the unresolved two-reading structure instead of declaring one reading true merely to make the merge work.

## 6. Current success can consume the route needed next

Now add a second, independently prepared replacement with alignment bit phi. Its future source-authorised repair again names abstract action 0, and its two concrete ports implement a xor phi. The old calibration service can currently answer queries about either theta or phi. No other interface exposes phi. All four combinations (theta,phi) are admitted.

Consider the following finite campaign:

1. Query B_theta.
2. Perform the first repair through r_theta.
3. Migrate the repaired state to the first replacement.
4. Retire the old service without storing phi or establishing another authorised observation route.

The current repair is correct. Its state and output can be preserved exactly at arrival. Nevertheless the two cases phi=0 and phi=1 now have the same successor information and require opposite legitimate ports at the next handoff. The same separation argument applies. The next task cannot be guaranteed under the remaining interface.

This does not show that the complete two-handoff contract was preserved and then failed. It shows that a certificate for the first contract does not certify the stronger continuation-capacity contract. If that stronger contract was promised from the outset, the retirement step lacks its required justification.

### Two bounded positive repairs

* Before retiring the old service, obtain the correctly bound phi observation and retain it in the successor. After the first action, theta can be discarded if no future task depends on it; the live successor need retain only the future-relevant phi bit plus applicable provenance and interface data.
* Preserve or lawfully replace the query service so the successor can obtain phi when it is needed. An address in a capsule is not enough: the service, permission, observation semantics and access path must survive.

For the fixed two-handoff model with no later observation, the complete action vector distinguishes four cases. A total pre-retirement transcript of fewer than two bits cannot support both exact operations over all four cases. Querying theta and phi attains two bits. This is ordinary counting, and refers to total acquired information, not a requirement for two permanent working-memory bits after the first operation.

A source that produces new calibration data only after later physical changes cannot be replaced by a finite table of earlier guesses. Conversely, a maintained authorised observation process may support successive tasks with bounded working memory. Thus repeatability is a claim about the surviving process/interface, not merely the byte size of the initial capsule.

No indefinite viable strategy is proved here. The finite example identifies the particular channel-removal operation that breaks the next step. Further repetition requires a stated task/disturbance class and evidence that the access/maintenance/authority conditions remain available.

## 7. Forking exclusive and shareable rights

The alignment bit does not resolve allocation by itself. If the original grant permits one selected successor to act, both copies of P cannot use B as two allocations. They need a common actual source allocation event or a currently authoritative shared mechanism selecting one. A correct alignment observation for each recipient is still only interpretation evidence.

If the source grant permits both recipients to execute their own scoped repairs, both can be warranted continuations. A merge may retain both contributions with their separate occurrences and shared acquisition origins. The resource semantics are supplied by the source, not by the mathematical fact that packets were copied.

There is therefore no general anti-fork identity principle here. The comparison must ask which claims/rights are shareable, which are consumable, and what the actual joint history has allocated.

## 8. What must be checked in an actual application

The model's key assumptions are empirical and normative obligations rather than certificate syntax:

1. The actual source occurrence and legitimate grant really identify the intended abstract operation and recipient.
2. The registered encodings describe the actual target realisers and preserve the full operative state, effects and readout on their stated domains.
3. The packet really leaves both mappings live; there is no already available discriminating information that the model ignored.
4. The calibration observation really discriminates the mappings without an unauthorised or destructive probe, and its result is current for this concrete realiser.
5. No undeclared alternate policy or harmless probing route already solves the task; conversely any promised future reread has real access, support and permission.

These cannot all be inferred from an unchanged digest, an epoch number, a returned receipt, a formal history isomorphism, or a successful run on one example. An empirical application should test the two encodings, the binding-loss export, both calibration outcomes, stale-target/version rejection and the service-retirement control.
