## Results and exact boundaries

1. **Type-indexed family controls.** Actual unchanged `HasE` derivations check the
   erased re-abstraction cycle and a structured-carrier observer. Under the
   explicitly stated projection/assembly/coherence contract, unrestricted families
   fail a coherence test, constant families give a nontrivial local repair, and
   the observer imposes an additional cross-instance condition. A classical
   diagonal excludes full impredicative products at an actually formed source
   self-instance. These are conditional semantic obstructions and exact source
   controls. They do not construct a whole `HasE` model, derive assembly equations
   from arbitrary membership soundness, refute every Henkin candidate, or supply
   either missing scalar/graph transport bridge.

2. **Church identity in finite all-Raw contexts.** For any finite telescope Γ made
   entirely of the literal unchanged Raw type and an actual `HasE Γ n N`, there
   is one finite count k and actual source identity
   `HasE Γ I (Id_N n (inputNumeral k))`. The same k works before quantifying over
   arbitrary source-polynomial substitutions at the observation-conversion level,
   and before quantifying over open valuations and arguments. This is an open
   source identity under the original Γ. It is not merely a family of results
   obtained after choosing closed instantiations.

The independent raw-context review strengthens the boundary: for every k and
proof polynomial r, there is no `HasE [N] r (Id_N(var 0,inputNumeral k))`.
Its actual FullPER evaluation at numeral k+1 and distinct iteration normal forms

This is stronger than failure of a proposed observation-reflection route.

No arbitrary typed-context canonicity, arbitrary-type completeness, untyped

## Portable retained-object replay

Requirements: Python 3.9+, Git, the exact Linux x86_64 Lean 4.19.0 distribution,
pinned external package checkouts with existing build libraries, and the exact
retained objects enumerated in `runtime_objects`:

- 92 baseline objects, including two inherited Mathlib overrides
- Four author closed-scalar objects
- Three author structural objects
- Three author closed-identity objects
- The author OpenDevelopments extractor object

One additional external Mathlib `Logic/Equiv/Defs.olean` is hash-bound. All 103
retained prerequisite objects and that extra external object are rehashed before
and after replay. Each group is supplied as a directory of module-relative object
paths. Use the `fresh_output` recorded in each original author FINAL_REPLAY receipt
for the scalar, structural and identity groups. Do not substitute other historical
objects merely because they carry the same module name.

First independently check the published successor ZIP hash, then extract it.
Use recipient-local paths and a new, absent output directory:

```sh
python3 replay_extensions.py \
  --archive /evidence/type-extension-preservation-20261010.zip \
  --lean /toolchains/lean-4.19.0-linux/bin/lean \
  --packages /retained/.lake/packages \
  --baseline-objects /retained/baseline \
  --scalar-objects /retained/author-scalar-final \
  --structural-objects /retained/author-structural-final \
  --identity-objects /retained/author-identity-final \
  --extractor-objects /retained/author-extractor \
  --out /replays/new-absent-output
```

The wrapper safely extracts and authenticates all four embedded predecessor ZIPs
under the separate output directory. It authenticates the inherited verifier
before calling only its prerequisite-verification function. It checks the 83
original source hashes/Git blobs, source and Mathlib pins, exact Lean executable
and version, package revisions, historical build receipts, and retained objects.
It performs no 83-module rebuild and repeats no predecessor scientific campaign.

Only the new type-family modules, their independent controls/dependency audit,
the exact reviewed raw-context modules, and independent boundary controls are
freshly compiled with `--trust=0`. Reviewer rejection fixtures must actually fail
compilation; they are distinguished from positive theorem checks. Fresh output
and logs go only to the requested output directory. Isolated library paths keep
old modules from shadowing new additions. The original source copies and input
bindings are rechecked after execution.

Add `--verify-only` to perform hash/pin/prerequisite checks without any module
compilation; this mode still uses a new output directory to unpack predecessors.
A hash-only success is explicitly not a fresh kernel-check result. The normal
`REPLAY_RECEIPT.json` records fresh positive checks, expected rejections, and zero
inherited modules recompiled. Original author/reviewer entry points are retained
as historical evidence; do not run them to reproduce preservation, because they
may contain old workspace paths or overwrite historical receipts.

## Trust and portability limits

This ZIP preserves the source/evidence closure but is not an independently
executable fresh-machine build. A new machine needs the exact toolchain, pinned
package source/build libraries, and retained object bytes. Rebuilding absent
objects is a separate source-build/rebinding operation requiring new receipts;
this wrapper intentionally does not perform it or silently accept new hashes.

Inherited object verification establishes byte identity and recorded provenance.
It is not fresh kernel compilation of the inherited baseline. The exact compiler
binary is hash-checked, not bootstrap-verified. External package revisions are
checked and their existing build libraries reused; apart from the explicitly
bound objects, those build outputs are not fully byte-audited or rebuilt here.
Only the listed new modules receive fresh trust-zero compiler checks in this run.

No protected repository is changed, and no upload, publication, integration,
owner acceptance or T20/#9 closure is performed or implied.
