## Claim-level assessment

### 1. Varints and numeric envelope

The Lean unsigned-varint encoder uses exactly the recovered Python unsigned LEB128 order, low-seven-bit mask, continuation bit, quotient recursion, and canonical re-encoding check. uvRead_eq_some_iff proves the exact accepted-prefix characterization, not merely selected roundtrips. The byte-list numeric encoder uses a leading 0x01 followed by the payload in big-endian base 256. decodeNumeric_eq_some_iff proves its range characterization.

The Bytes premise on numeric roundtrip and injectivity is essential. Lists of arbitrary naturals are not byte strings: encodeNumeric [0,256] equals encodeNumeric [1,0]. A malformed non-byte list must not be used to generalize these theorems. Python bytes already enforces this domain; Python's refusal of negative integers and booleans is a separate host-type matter outside Lean Nat.

### 2. Program wire format and decoder scope

Expression tags 1–10, statement tags 16–19, magic P02L plus version 1, arity/output headers, varint operand order, and the sentinel numeric envelope agree with the recovered source. Generated binary Seq is serialized as a valid two-child Python Seq; skip is a zero-child Seq.

The Lean reader lowers arbitrary variadic Seq to binary Seq/skip. Consequently, accepted arbitrary Python syntax is not generally preserved byte-for-byte by decode then re-encode. A one-child Seq containing one assignment decodes to that assignment and re-encodes without the Seq wrapper. This is intentional normalization, not a defect in the stated generated-code roundtrip. sequenceList_execution proves ordered-fold semantics of the lowering.

The parser's depth fuel is structural; generated AST depth is bounded by generated byte length. decodeBytes_encodeBytes and decodeIndex_programIndex prove all generated codes roundtrip. They do not prove Python parser equivalence for every malformed byte string, host recursion failure, or Python's early impossible-child-count rejection. Finite differential mutation tests are supplemental evidence only.

### 3. Evaluation, arity, input order, and resource semantics

The numeric evaluator requires arity two, initializes register 0 with n and register 1 with word, initializes all other registers to zero, executes the retained ObserverCore LOOP semantics, reads the declared output register, and reduces modulo two. The source Python evaluator does the same on a successful unbounded run. Invalid syntax or the wrong arity denotes zero.

evaluateIndex_programIndex and parameterIndex_correct are universal Lean statements. The latter inserts parameter a as the first argument of a fixed ternary program, leaving n and word as the two runtime inputs. Independent controls use a noncommutative difference program and a first-argument projection so swapped inputs or a misplaced literal cannot hide behind addition's commutativity.

LOOP bounds are captured before iteration; the loop register receives successive values 0 through count−1 and may be overwritten by the body. Expression subtraction is truncated; division by zero is zero; remainder modulo zero is its dividend. These match the recovered source.

The mathematical evaluator has no step or integer-bit budget. Actual Python defaults do. Explicit Python probes confirm exhausted step/bit budgets raise ResourceLimit instead of returning semantic zero. No theorem here equates a bounded failed runtime with the total mathematical result, proves a uniform practical runtime bound, or formally verifies Python's stack interpreter.

### 4. Actual primitive-recursive numeric specialization

parameterIndex p a is the actual sentinel-prefixed integer encoding of the specialized program. parameterIndex_primrec proves Mathlib Primrec of the numeric map a ↦ parameterIndex p a for every fixed Program 3 p. It does not replace the function with an abstract naming convention or an assumed index oracle.

The proof uses exact varint and numeric encoders. The variable part of the fixed program's byte list is an actual constant-expression literal. The program p is fixed before the Primrec assertion. Extensional PR coverage supplies the existence of one fixed program for the family; it does not extract executable code from arbitrary erased Primrec proofs. There is no claim of a uniformly primitive-recursive universal evaluator on arbitrary program indices, nor is one needed by the reduction theorem.

### 5. Actual observer equality and precise lower bound

Pi3Program.numeric_observer_eq proves equality of the entire ObserverCore.output function with the tagged Pi3 observer, on every infinite binary input and every output position. It is stronger than matching sampled prefixes or merely matching defect. The finite-prefix construction supplies sentinel-coded prefixes and handles the all-true source branch; the equality then transfers the already proved fair-Cantor tagged measure law.

For each fixed decidable relation R(a,i,s,t) with joint Mathlib PrimrecRel, Pi3IndexReduction.exists_primrec_zero_defect_reduction proves:

- There exists f : Nat → Nat with Primrec f
- For every a, f(a) belongs to zeroDefectIndices exactly when ∀i ∃s ∀t R(a,i,s,t)

The companion theorem gives strictly positive defect exactly when ∃i ∀s ∃t ¬R(a,i,s,t). Positive defect is not automatically defect one or atomlessness: multiple tagged rows can yield intermediate defect.

This is a genuine primitive-recursive many-one lower-bound map for the stated primitive-recursive normal forms. Calling it full Pi3-hardness requires identifying the chosen hierarchy convention with those normal forms, or supplying that separate normal-form theorem. No arithmetical membership upper bound or completeness classification is proved here. The target set also contains invalid codes that denote the constant-zero observer; generated reduction outputs remain valid by roundtrip, so this does not undermine the lower-bound direction.
