# Dependency identity and trust

`ninth/DEPENDENCY_PINS.json` is the unmodified dependency authority: Lean 4.19.0 Linux x86_64, executable SHA256 92c3d35b5bfaa5e0fea413a775d504cf46cd95e1345df61c2274f76779e7e023; Mathlib revision c44e0c8ee63ca166450922a373c7409c5d26b00b; eight exact package revisions. The official Lean release archive used in verification has SHA256 6fe3ce97a58f44e2b3567d455b994eacec5bfe9ae7774f2a573444480ba813fe.

Mathlib's `.lake/packages/` must contain exactly the eight pinned package names. Existing symlink checkouts at that package-registration boundary are supported; their resolved roots are protected from output writes. Every package must be at the pinned clean Git revision without unexpected Lean sources. The optional unchanged Ninth official Mathlib source-archive identity route remains available through `--mathlib-archive`; other packages still require their clean exact Git checkouts.

`DEPENDENCY_OBJECTS.json` contains identities only, never object bytes. It binds the external dependency object census, sizes and SHA256 values before and after replay. Most theorem objects were acquired through the pinned official Mathlib cache client and official package artifacts. Cache-client tooling itself was locally built from pinned source. No historical project object is reused. This is **not a cold build of the dependencies**, nor a proof that cached object bytes follow from source solely by the checks in this packet. The official cache distribution and toolchain remain trusted.

The full project closure is freshly compiled from this packet, in absent output directories. Dependency libraries are checked for colliding project module objects. The object search path is explicit and excludes caller paths and all author/reviewer project build lanes. This environment-dependent dependency manifest is intended for the exact official-cache replay mode; an independently cold-built dependency environment with different object bytes needs its own independently justified environment receipt rather than silently weakening the identity gate.

Kernel proofs depend only on the audited standard logical axioms. Native execution additionally trusts the pinned Lean runtime/compiler, standard implementation redirections and external arithmetic/array/string primitives. C generation is reported honestly as code generation; no linked executable or compiler-correctness claim follows.
