# Actual reading and replay accounting

The controlling chapter was built from actual original reports, exact theorem-source excerpts and final reviewer records, not only the orientation summaries. `READING_LEDGER.jsonl` records 78 read/excerpt events (including repeat reads); `SOURCE_REGISTRY.json` identifies controlling cited bytes and all catalogue provenance locations. A source appearing in the registry or static closure is not thereby claimed fully proof-audited.

The ledger records the requested/read excerpts and their hashes. Some early combined tool outputs were truncated; a `direct full text` entry records that a full text was requested, not an assertion of a line-by-line independent proof audit. Important current statements were checked against later complete reviewer reports and targeted theorem declarations. Earlier direct reads performed before the helper was created are explicitly labelled retrospectively logged. The numbered statement records give their actual assurance category rather than turning all text reads into kernel verification.

Read-only source work included:

- original P02 ordinary codec/correspondence and hierarchy proofs;
- actual residual-frontier, grounded/guarded compilation, attainment, numeric and witness reports, and shared-cost/guarded-DAG reports with final repairs/reviews;
- old completion orientation as historical context, whole-HasE faithful-PER and homogeneous-Henkin reports, final independence review, actual source soundness/application declarations;
- actual-E induction/rigidity and Sigma interfaces, literal-principle separation, direct full-rule/J syntax and theorem sources, computation/recursor uniqueness, actual-N extraction and Raw gap, and erased-J proof uniqueness;
- actual source-code presentation/checker/search reports and independent ACCEPT;
- source sidecar and rational joint-kernel reports/reviews, exact stopping report and independent review;
- alternative rational-shift/threshold reports, literal ordinary and kernel execution reports/reviews, latest literal probability report/review and exact defect/first-bit declarations;
- productive/root-signature identification, general-rank and CRT reports, and the finite-score skyline report plus final scoped PASS review.

The original standalone archives named Joint_Completion_Soundness, Full_Rule_Independence_And_Positive_Consequences, Joint_Structural_And_Mixed, and Original_Package_Extraction_Fidelity were not recovered under those names. Their exact Lean sources are retained in later source chains. Claims relying on those files say **direct source plus retained downstream evidence**, not an invented original standalone review. The catalogue owns the exhaustive unmatched-name register; absence of a historical archive name is separate from absence of source bytes.

Fresh work was deliberately narrow:

1. Exact unchanged rational joint-kernel Python replay in a fresh copy, ordinary and optimized mode: 162 controls and 125 probability rows both pass, identical stdout. The receipt lists source hashes and commands. It includes the corrected actual D1 quotient/coarse-state map. This is bounded execution evidence, not a new universal proof.
2. Currentness of the literal probability independent-review bindings: 90/90 source/receipt/artifact hashes match. This is integrity checking, not a new Lean build.
3. Static isolated source-import closure reconstruction: 23 formal clusters, all selected local imports resolved, with explicit unchanged module hashes and eight ordinary-code owner clusters. The exact literal unchanged closures are nine modules for execution and 41 for probability (34 baseline plus seven literal). Static closure is not compilation. Mathematical dependencies and claims of original receipt matching are kept distinct from the import graph.

No unchanged Lean suite was rebuilt, no source archive was edited, and no protected repository state was changed. For a later targeted replay, use `FORMAL_REPLAY_MAP.json`, verify current bytes and the historical binding receipt, reconstruct missing environment/launcher paths transparently in a derived scratch copy, and rebuild only affected modules. A public source projection can be replay-oriented without containing all historical tools, caches, private paths or inputs.
