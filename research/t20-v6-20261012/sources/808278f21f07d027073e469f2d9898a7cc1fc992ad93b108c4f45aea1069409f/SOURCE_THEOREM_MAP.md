## Executed rather than kernel-proved application

`occurrence_model.py` supplies controlled JSON encodings, `here` plus person/time context, source/carrier distinction, full-record anchored authentication premises, bounded prospective adoption, model-derived office membership and practical applicability. `continuation_model.py` supplies actual source-reading constructors, registered endpoint binding, predecessor retirement, read/write/denial semantics, two migration phases, all 64 profiles per fault model and computed support families. Its operational monotonicity is exhaustively verified for those finite profiles; it is not inferred from its name.

The finite Python semantics is not extracted from Lean or a verified compiler. Agreement is established at the stated specification/implementation correspondence and independently tested scope. The generic Lean theorem can be applied mathematically once these finite model facts are supplied; no machine-level proof that Python implements Lean is claimed.

The full-record anchor maps are trusted input relations. They prevent changing the rule or occurrence while retaining its event identifier inside this model. They do not cryptographically authenticate the relation or defend against arbitrary external mutation of the interpreter's memory. World object identity checks prevent a caller from substituting a same-ID token for the registered parent or service endpoint; actual-world object authentication remains outside the reference model.
