## Read a claim

Start with its full statement in [RESULT_STATUS.json](RESULT_STATUS.json),
including domain, assumptions, conclusion, limitations and source owners.
Read the selected original source and review through
[SOURCE_MAP.json](SOURCE_MAP.json). Then inspect its exact statement, target and
receipt bindings in [EVIDENCE_BINDINGS.json](EVIDENCE_BINDINGS.json). The
[registry](../../../experiments/orthemology-v5-successors/registry.json) binds
these records and each suite descriptor by content hash.

Custody, inherited review, fresh execution, implementation reach, scientific
disposition, empirical or normative warrant, external review and adoption have
separate fields. A record may contain affirmative reviewed mathematics while
its fresh-kernel field remains unrun. Formal components do not promote a whole
written classification. Counts of modules, targets and repeated readbacks are
not counts of independent theorems or independent reviews.

## Source interpretation

`EXACT` means the public payload matches the selected source bytes. `DERIVED`
requires a recorded original-to-public map and reviewed transformation.
`CUSTODY_ONLY` records an input identity without publishing its payload. Exact
duplicates can have several original aliases and one public storage object.
Those aliases do not create new independent evidence.

Source-owned relative paths may describe members of an original archive or
declared external inputs. They are resolved using the exact input and member
chain, not by an unrelated file with the same basename. Runtime-generated
reports, private locators and compiled objects are not promised checkout files.
Projection restores only the selected suite's declared closure into a fresh
external directory.

Research result selectors and historical source succession serve different
purposes. A later correction supersedes only its stated earlier scope; it does
not rewrite the earlier report or close an unrelated obligation. In particular,
the original U01–U14 and CV-R/CV-C/CV-O burdens, candidate E/G, T354, PMR007,
Ten Advances and Connes-specific statuses retain their original owners.

## Review boundary

Repository integration and fresh scientific checks are distinct from external
specialist review, a new participant experiment, empirical validation, normative
warrant or adopting a candidate identity judgement. The exact PR head, tree,
local workflow receipts and actual GitHub CI state are returned in the PR review
handoff. The tracked registry contains no self-referential final-HEAD digest.
