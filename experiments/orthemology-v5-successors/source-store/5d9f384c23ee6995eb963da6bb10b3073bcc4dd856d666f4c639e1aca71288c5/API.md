# Exact reference API, version 1

Import modules directly after adding this directory to `sys.path`. No installation.

`validate_model(raw)` accepts a dict with exactly `n_states`, `n_actions`, `initial`, `menus`, `rows`, `priorities`. Dimensions and indices are plain Python integers (not bool). `menus[s]` is a nonempty increasing list/tuple of actions. `rows[mode][state][action][receipt]` is an integer or canonical rational string (e.g. `"1/3"`); even unlawful-action rows exist and are validated. `priorities[mode][state][action]` is a natural integer. All arrays accept list or tuple. Result `Model` has the same named fields, frozen nested tuples, and Fraction rows. An existing Model is validated too.

`component(model, theta, pairs, uncertain=False)` and `reachable(model, source, pairs, theta, compatible_only=False)` operate on finite pair collections. `known_operator(model,K)` and `uncertain_operator(model,K,W)` return frozensets.

Certificate bodies are frozen dataclasses or dicts with EXACTLY the corresponding fields. Sequence fields are tuples (not lists); finite sets are lexicographically increasing and duplicate-free. Models deliberately have a convenient input encoding; certificate syntax deliberately has one finite canonical encoding.

- `Route(source, steps, component, reveal)`: `steps` is a tuple of `(action, receipt)` internal edges. The states visited, including the initial source and endpoint, are all distinct; at most n_states−1 steps. `component` is an index or None. `reveal` is a final `(action, receipt)` or None. Exactly one of component/reveal is non-None. Known routes cannot reveal.
- `Positive(K,W,D1,D,known_components,uncertain_components,known_routes,uncertain_routes)`: regions and pairs are canonical tuples. Each component is a nonempty canonical tuple of pairs. `known_components` is a canonical tuple of components; `uncertain_components` is exactly `(components_for_0, components_for_1)`, each canonical. `known_routes` is a tuple of Route (or exact-field dicts), in increasing source order, exactly once per K state. `uncertain_routes` is exactly `(routes_for_0, routes_for_1)`, each increasing and exactly once per W state. Extra unused qualifying components are permitted.
- `Negative(k_trace,w_trace)`: each trace is a tuple of canonical region tuples; starts with all states; successive entries are exact operator updates; all updates before the last strictly decrease; last two entries equal. At most n_states strict decreases, so at most n_states+2 entries. Initial state must be absent in terminal W.

`check_positive(model, raw_body)` and `check_negative(model, raw_body)` return normalized checked dataclasses, or None for a malformed/invalid body. They never infer acceptance from a success flag. `solve(model)` returns a Positive or Negative. Model validation exceptions and resource exhaustion remain execution errors, never a negative answer.

`initial_memory(model, positive)`; `choose(model,positive,memory,state) -> (action, prepared_memory)`; `observe(model,positive,prepared_memory,state,action,receipt) -> Memory`; `action_for_history(model,positive,history) -> action`. History is a nonempty odd-length list/tuple `(s0,a0,s1,...,s_t)`. Every index and every historical action must be lawful; otherwise ValueError. An alternate initial state, impossible receipt, off-policy action, or certified-invariant failure invokes persistent first-lawful-action fallback. Incremental choose/observe require a checked Positive; initial_memory validates it. Memory is frozen and contains phase, known1, retained, departures, uses, receipts, fallback, prepared_state, prepared_action. Counters are unbounded integers. `rejection(model,memory)` and `threshold(model)` expose the exact rational test for independent controls. No runtime API accepts the actual mode or observed priority.

Independent checking must not assume solve is correct. This is executable finite evidence, not a mechanization of the ordinary probability proof.

Impossibility is history-dependent: before known1, a receipt is impossible only when both rows assign it zero; after known1, any P1-zero receipt is impossible even if P0-positive. The known1 flag is never cleared. Incremental calls trust a Memory produced by the same model/body and these routines. Arbitrarily constructed Memory is not certified reachable. Use action_for_history for a fully syntax-validated policy on raw histories. It accepts a checked Positive or validates a raw body; incremental choose/observe require the normalized Positive.
