# Independent informational countercontrols for runtime clocks

## Finding

Equality of compressed accepted-receipt laws and parity-preserving finite stuttering do not establish observational equivalence for arbitrary physical policies. The positive refinement of a controller whose action/memory are frozen through waits can remain correct. A converse winning-region claim needs a separate interface preventing extra information from timing, public frames or environment random bits.

These are exact counterexamples to that inference from a marginal-law premise. They do not assert that every canonical sampler, or the pending frozen implementation, leaks information in the displayed manner.

## 1. Identical receipts, distinguishable waiting

The logical model has two hidden environments, a single observed receipt 0, and two actions 0 and 1. Both environments return receipt 0 with probability one after every action. The coBüchi priorities are 2 when the action equals the hidden environment and 1 otherwise. No common logical policy can satisfy both objectives: its observed law is identical in both environments, while a single action sequence cannot eventually be all zeros and eventually all ones. The digest-qualified accepted solver independently proves this negative result for an explicit finite embedding in `same_receipt_no_common_logical_policy`.

Now implement both environments using independent fair two-bit blocks. Environment 0 accepts every block and emits payload 0. Environment 1 accepts 00, 01 and 10, emits payload 0, and rejects 11. Both implementations have exactly the same accepted logical receipt law. They can be regarded as rejection samplers with denominator/weight 4/4 and 3/3 respectively. Marginal equality alone does not require a reduced or common denominator certificate.

If the physical policy can see rejection/wait status at block boundaries, the first rejected block proves that environment 1 is active. Play action 0 until a rejection, then action 1 forever. In environment 0, no rejection occurs and every action is good. In environment 1, a rejection occurs almost surely; its block count is geometric with parameter 1/4 and mean 4. Thus the physical policy makes only finitely many bad choices almost surely, with expected eight bad acquisition ticks under the stated pre-receipt charging convention.

This physical policy is deliberately outside a frozen-memory positive adapter: it changes the action after a rejected wait, before accepting the pending logical receipt. It witnesses why arbitrary physical policies cannot automatically inherit the logical negative certificate.

## 2. Equal clocks, exposed environment bits

Use one bit per receipt in both environments. In environment 0 return the bit itself; in environment 1 return its complement. Both accepted receipt streams have the same iid fair law, and both clocks are identical. Nevertheless, the pair (raw environment bit, emitted receipt) reveals the hidden environment immediately by comparison.

Again, the logical opposing coBüchi instance has no common winner, while a physical policy that sees this pair can choose the correct action from its second step onward. Hiding the raw environment bits restores the intended receipt-only information boundary. Equalizing denominators/timing alone would not prove that boundary for arbitrary exact sampling implementations.

## Required separation in a positive adapter

- Environment randomness: the fair input tape used internally to implement transition sampling
- Public implementation output: acknowledgment, payload, action and any framing fields, including their physical timing
- Controller-observable history: the compressed logical receipt/action history available to the fixed controller, excluding internal rejection bits and raw random bits
- Cost labels: the already chosen pre-receipt state/action pair retained throughout the acquisition interval, including the acceptance tick

The controller table may be common across environments even though the generative simulator's P02 index depends on an environment parameter. That simulation contract does not grant the deployed policy access to the true environment and does not turn multiple distinct environment laws into one fixed-index/fixed-fair-input law.
