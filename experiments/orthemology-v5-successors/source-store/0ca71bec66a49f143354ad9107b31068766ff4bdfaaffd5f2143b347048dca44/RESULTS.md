# Result and limits

## The operational gap

The accepted attribution results concern a fixed hidden one-class map and actual-root faults. The accepted typed history has independently indexed label memories. Shared physical failure provenance alone does not equate those memories or establish coherent root-wide control.

For the declared implementation with one shared store per actual root, literal state equality fails. A good shared root may prepare or cancel a complete command through one selected label and thereby store it at an unselected alias. In every reachable accepted common history, a good label can acquire that command's commitment or tombstone only if the command selects that label. The generic selected-memory invariant and resulting literal-pullback obstruction are kernel proved. The seven-label controls show the corresponding concrete events are lawful, not merely hypothetical malformed updates.

A separate stronger claim about impossibility of every receipt-preserving revocation-history encoding remains ordinary analysis; it is not presented as one of the kernel results. Exact receipt-update controls establish the narrower verified fact: one shared-root closure records only the real responding label.

## The proved replacement

The model fixes a nonempty alias class A and a horizon-wide actual faulty set within the actual root image. If B bounds actual faults, the accepted attribution theorem derives the label bound k=B+|A|−1. The common configuration uses m labels and budget k, with q+r>m+k and q+k,r+k≤m. It does not count labels as independent actual roots.

Each actual root has one store. Concrete operations address labels, route to that store, and retain full commands. The map and fault set are mathematical environment parameters; this package constructs no controller, root-identification channel or selector service. Authentication, legitimate control, actual wiring and physical shared-store correctness are not derived from the data structures.

The refinement relation keeps plant, epoch, pending state, genuine label acknowledgements, certificates and full-command cancellation acknowledgements exact. At every good label:

- The stored policies agree.
- Abstract commitments are the shared concrete commitments restricted to commands selecting that label.
- Abstract revocations and tombstones are subsets of the concrete shared veto stores.

Consequently concrete permission implies abstract permission. The converse fails in a checked extra-veto example. Root-wide preparation can expand into internal abstract preparation steps at selected aliases. Root-wide policy delivery can expand at all aliases using the same already-certified source policy, including delayed or repeated delivery. These steps manufacture no label reply, owner acknowledgement or cancellation receipt. Completion requires exactly r real receipts, matching the accepted common rule; excess receipts are not silently discarded.

Every concrete transition and finite trace has a common witness trace under this relation. The entire ordered list of genuine landing commands, requesters and times is preserved. The expanded event list is a proof witness, not an actor-visible transcript or a costed schedule.

## Typed consequences and source-gate boundary

The specialization uses the unchanged typed Plant, full ordered Envelope and imported localStep. It derives:

- Current full-policy authorization at each concrete reachable landing
- Exact installation and repair successor records, including all history/version changes
- Finite-history preservation of the full source and custody frame
- Four exact installation/repair version and history-length counter laws
- Persistent goals and permanent exclusion of an already-executed fixed action
- Permanent exclusion after a certificate of more than k real cancellation labels

The gate adapter represents each shared store exactly to the unchanged compiled-source local gate. Its literal common snapshot is explicitly not asserted reachable. Reachability instead comes from the separate weak simulation. For the unchanged one shared badOpen Boolean, successful source attempts imply concrete landing; with badOpen=true the predicates are equivalent. Withholding may add rejection. Successful attempts have the entire concrete successor plant, and rejected attempts preserve their complete gate snapshot.

This is not a whole runtime-state or lifecycle match. The adapter does not reconstruct completed-certificate lists and does not claim the old label-local preparation/cancellation/certification macros implement shared-root storage.

## A concrete typed witness

The witness has seven labels, six actual roots, alias class {0,1}, actual B=1, lifted k=2 and q=r=5. Root 6 is the bad singleton. It reuses the accepted compact three-byte source fixture and a full installation command with ordered path [0,1,2,3,4]. Four concrete preparation events at labels 0,2,3,4 update four actual shared stores and ready all five selected gate occurrences. The exact source attempt is proved successful and returns the complete installed plant.

A separate still-unlanded branch cancels on exactly labels {0,2,3}. Alias 1 closes through its shared store but is not counted as a reply. This valid three-label certificate blocks later source attempts even though the original typed localStep is still version-valid. It is a non-vacuous cancellation control rather than a replay/version mismatch.

Equal nonce and equal finite path support do not identify a reordered full command. Full ordered path and successor remain part of the memory key. Five isolated source mutations are rejected for their intended failures: using B as label budget, inventing alias acknowledgements, cancelling at the wrong actual store, reversing the veto inclusion, and dropping the selected commitment mask.

## What does not transfer

The accepted exact actual-root cost 3B+2|A|−1 applies to the retained fixed-family interface. The covering lower bound additionally needs its exact full-transcript opacity premise. Neither is made into a new implementation theorem here.

The previous reference runtime's default batch still enumerates four three-label paths. Generic root-count gate theorems do not turn it into a native executed 21-path unknown-class controller. Such a controller would need a separately specified portfolio, real per-label service/replies, cancellation scheduling, stable authorization windows and horizon/clock accounting.

The new safety simulation proves no observation equivalence, map secrecy, strategy discovery, bounded progress, opaque failed-transcript construction or attempt optimality. Partial epoch delivery, partial cancellation, out-of-path queries, exposed internal state or timing channels could reveal mapping information. Richer information may leave safety upper bounds intact while invalidating an opaque lower-bound premise.

The raw2-to3 lifecycle extension is not imported. The positive witness is one raw0 installation and a cancellation branch, not a two-stage controller. No physical-world warrant, enlarged R5, N2/T0 conclusion or canonical/tranche closure is asserted.
