## Portability and omission boundary

This is source/evidence preservation plus verified retained-object replay.
The retention route works in the preservation environment; extracting these four
ZIPs alone is not a fresh-machine executable build. A new machine needs the pinned
Lean distribution and package sources/build libraries, then either the exact
retained objects or a new source build with trust-zero checks, explicit dependency
rebinding, and new object receipts. Relocated Lean builds can produce different
object bytes. This wrapper does not implement that bootstrap/rebinding route and
does not claim rebuilt objects have historical hashes.

The Lean executable is hash-checked, not bootstrap-verified. Existing external
package build libraries are reused at verified Git revisions; their entire build
output is not independently rebuilt or byte-audited in this preservation run.

Twenty-four redundant object snapshots from the three new frozen directories are
omitted, with original paths/sizes/hashes in `new_snapshot_omissions`. The 111
unique inherited historical object bindings are also inventoried: runtime
requirements are distinguished from historical evidence not rechecked by the
portable replay. Retained runtime objects are external inputs; absent historical
snapshots are never silently asserted present. Original review manifests remain
unchanged even where they reference an explicitly omitted object. The new
preservation receipt records what was actually rehashed and freshly executed.

Original author/reviewer scripts are preserved as historical evidence and may
contain workspace-specific paths or overwrite historical outputs. Use the new
top-level wrapper, which never runs those mutating entry points. No repository
changes, upload, publication, integration, or research closure are performed.
