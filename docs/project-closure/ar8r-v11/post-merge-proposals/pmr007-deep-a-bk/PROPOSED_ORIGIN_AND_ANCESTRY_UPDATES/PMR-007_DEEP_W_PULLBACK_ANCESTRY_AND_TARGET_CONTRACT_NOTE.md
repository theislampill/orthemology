## 3. Target-contract custody

The repaired finite key is:

```text
(target_id,
 target_version,
 recipient_scope,
 analysis_version,
 referent_id,
 semantic_contract_digest).
```

Each coordinate has a separate authority burden:

```text
target_id:
  registry identity, not target truth;

target_version:
  version custody, not semantic continuity;

recipient_scope:
  applicability boundary, not authorization by itself;

analysis_version:
  declared analysis custody, not world completeness;

referent_id:
  requires independent H16-style referent identification;

semantic_contract_digest:
  protects byte identity of a declared contract, not adequacy of that contract.
```

The full key is therefore a fail-closed finite model, not a claim of universal
contract completeness.

## 4. Source and world firewall

A source field or referent field can be copied. Equality of identifiers does not
supply:

```text
source-byte authenticity;
Arabic-primary verification;
translation adequacy;
source proposition reconstruction;
world truth;
revelational identification.
```

Likewise, adding a world-bridge object to an iterated pullback does not validate
that object. It only guarantees that the already admitted components address
one declared contract.

## 5. Common-bearer firewall

A categorical pair is not one numerical or metaphysical bearer. The pullback
object records a compatible tuple. Additional co-instantiation, identity,
intentional-ownership, or causal-realization premises are still required.

This keeps Deep W compatible with Deep G, Deep M, and the R5 plural/impersonal
controls.
