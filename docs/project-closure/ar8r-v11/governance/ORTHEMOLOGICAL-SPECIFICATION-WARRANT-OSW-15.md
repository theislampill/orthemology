# Orthemological specification warrant: OSW-15

OSW-15 is the current reusable gate for moving from a source claim to a formal, implementation, or world-directed conclusion. It refines the earlier eleven-coordinate proposal by separately tracking source/formal claims and objects, hypothesis/conclusion correspondence, build/kernel receipts, and custody. It preserves every earlier burden; it is not a competing shortcut.

The fifteen independent coordinates are: `source_claim`, `source_object`, `formal_claim`, `formal_object`, `interpretation_map`, `hypothesis_correspondence`, `conclusion_correspondence`, `scope_boundary`, `transport_witness`, `falsifiers`, `axiom_inventory`, `build_receipt`, `kernel_receipt`, `mathematical_review`, and `custody`.

`BUILD_PASS` licenses only acceptance by the exact declared toolchain. `KERNEL_PASS` licenses only the exact formal proposition under its exact axiom inventory and trust boundary. Neither establishes that the formal object represents the intended source object or that the intended mathematical theorem is true. Static token absence, source presence, declaration-name similarity, and model-generated review are not substitutes for object-level review.

Any load-bearing `FAIL`, `UNKNOWN`, `NOT_RUN`, or `NOT_PERFORMED` blocks theorem-intent promotion. The false-meniscus incident, T354 formal defect, T299/T300 proxy failure, Ten Advances 38/42 conflict, and Connes-rigidity dispute are distinct cases governed by this framework; OSW-15 does not merge their identities.
