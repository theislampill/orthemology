# Contributing research

Start by finding the strongest existing work and its review with `python tools/corpus.py search QUERY`. Read the [current-science](docs/reader/CURRENT_SCIENCE.md) and [frontier](docs/reader/RESEARCH_FRONTIERS.md) routes for the question. A result already established under stated hypotheses is not an open problem merely because its original source was stored in a historical collection.

## Source ownership

Edit the primary argument, proof or application source. Preserve its assumptions, exact scope, references and current review status. The ordinary collections are `papers/`, `foundations/`, `mathematics/`, and `applications/`. The [source schema](corpus/schema.json) and source-owned records distinguish an original edition from a new proposed edition.

The complete historical baseline is immutable. A new source or corrected edition receives an explicit version and exact identity; preserve the predecessor before changing the selected edition. Do not edit a generated work/status index to create acceptance. Attribution, supersession and publication decisions must be made by the relevant accountable owner and bound to the complete reviewed source.

For a new edition, put the scientific metadata in the source itself: initial JSON frontmatter delimited by `---`, with schema `orthemology-work-v1`, a meaningful `id` and `title`, explicit `statement`, `hypotheses`, `scope`, `responsible_owner`, `kind: finding`, and `status: proposed`. Use the four complete executable scenarios in [the maintenance tests](tests/test_maintenance.py) as fixtures for the source and review formats; their simulated decisions are not real approvals.

Register exact path, version, byte length, mode, SHA-256 and Git blob in `current_sources` in the lock; `current_works` contains only the selected source locator (path, version, and a JSON pointer for a JSON owner). Preserve and commit an old edition before replacing it, or retain its verified source object in approved custody. Do not leave its only recoverable bytes in a temporary cache. The provider can retrieve the declared exact blob from retained Git history. Add any new primary owner to the ordinary profile explicitly and account for its file cost; assembly rejects an omitted current owner and does not silently raise the approved budget.

Current authority views are generated by `tools/authority.py`. Run `python tools/authority.py generate --root .`, then `python tools/authority.py validate --root .`, using the explicit `--cache PATH --offline` options when appropriate. Validate the owners and regenerate the projections together; unsupported status promotion, missing original works and altered source bindings fail validation. Public coverage does not authorise access to or publication of a private primary work.

## Reading and reproduction

`tools/corpus.py` provides named reading, search, edition comparison and exact source recovery. Reading must not execute research code. Restored sources go to a fresh external directory; the provider rejects unsafe paths, wrong versions, corrupt bytes, reused destinations and incomplete recovery.

`tools/replay.py` owns the fixed proof, finite-control and publication recipes. It retains the original validators and denominators in exact recovered contexts. An export, an old receipt, a missing compiler or a successful finite control is not a fresh kernel proof. Missing dependencies stay visible.

Keep new experiments and replay outputs outside the normal checkout. Commit the actual scientific source, reviewed decisions and minimal reproducibility bindings. Do not recreate per-checkpoint source copies, hash-directory trees or a second historical chronology register.

## Review and integration

Changes must identify their scientific or engineering owner, source edition, actual tests and remaining limits. Add a regression test for a changed integrity or runtime contract. Run the affected controls and source projections; do not rerun unchanged accepted science solely to produce another receipt.

A source move cannot silently break an old path-sensitive consumer: either preserve its exact restored context or independently qualify an explicit replacement. Exact preservation and named access precede removal.

Branch implementation, external archive custody/publication, merge and issue closure are separate permissions. The open consolidation work order records the current scope and receiving gates. A green CI result does not establish scholarly comprehension or whole-programme scientific acceptance.
