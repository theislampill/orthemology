# Polymorphic identity source-normalization boundary

This is a bounded corollary of inherited machinery, not a new normalization programme. The literal polynomial is `app(app(atom S,atom K),app(atom K,atom Omega))`; its evaluation is `S K (K Omega)` in every environment. A retained Type-valued old derivation is supported at zero, erases to the old Has certificate, and translates exactly to the accepted P01AC polymorphic identity type. The target is inhabited by the inherited finite identity certificate.

Application has the explicit S then K two-contraction path to its argument. The unapplied source term has no normal reduct under the inherited full contextual reduction. Source confluence and finite normalization imply that no source-Conv-related FiniteDerives representative exists at any finite type. The result uses the old Raw rule and was already available before recursive dependent All. It does not concern all evaluation strategies or exclude a PER/extensional identity representative.

No atom/application bridge, eta rule, abstraction congruence, source-conversion typing rule, new axiom, or accepted-source edit is introduced. Existing Omega and discarded-expansion results are imported unchanged. The single conjunction `P01NormalizationBoundary.boundary_control` binds the same polynomial and source term across positive and negative claims.

## Reproduction

Set `TOOLCHAIN_ENV` to a trusted readable environment file exporting `LEAN_ROOT` and the pinned dependency `LEAN_PATH`. Run `scripts/reproduce-all.sh`. It uses the hash-verified Lean 4.19.0 binary, one serial compiler, `-j1`, default limits, and 180 seconds per module. Coordinate any other compiler work externally to keep at most two global processes. The sources were reconstructed recursively from actual import statements and compared with the accepted source manifest, without reusing accepted object files.

`SOURCE_IDENTITIES.json` records all source bytes. `ACCEPTED_INPUTS.json` records the exact unchanged inherited closure and its upstream manifest digest. `dependency-order.txt` is the dependency-first source order. `BoundaryReadback.lean` prints every new declaration, its exact definition/type, and its transitive axiom list, with the inherited executable axiom gate. Fresh reproduction logs go only in `reproduction-logs`; immutable verification evidence is kept separately in `evidence`.

Kernel build evidence and independent proof review are separate acceptance stages; consult their explicit receipts rather than inherited source comments.
